# Красота с любовью — бьюти-пространство в Гатчине

Статический сайт, собранный по референсу клиента. Без сборки и зависимостей —
открывается как есть, кладётся на любой хостинг / GitHub Pages.

Живая версия: https://likes32.github.io/Krasota/

**Перед каждой выкладкой:** `node tools/version.js`. Скрипт ставит в ссылки на стили,
скрипты и фото отпечаток содержимого (`styles.css?v=1a2b3c4d`). GitHub Pages разрешает
браузеру 10 минут не перепроверять файлы — без отпечатка телефон после выкладки
ещё до 10 минут показывает старую версию. С отпечатком изменившийся файл получает
новый адрес и скачивается сразу.

## Структура

```
index.html        Главная: хиро, «Наше пространство», «Направления»,
                  Обучение (#obuchenie), Мастер-классы (#masterclasses),
                  О нас (#about), CTA-полоса, подвал
services.html     Услуги: 6 направлений — брови/ресницы у Анастасии (DIKIDI), остальные «мастер на выбор» (подбор по телефону/MAX)
coworking.html    Коворкинг: преимущества, аренда (час / 8 часов / месяц),
                  типы рабочих мест, CTA-полоса
contacts.html     Контакты: блок записи (#zapis), реквизиты, статичная карта
privacy.html      Политика конфиденциальности (152-ФЗ); ссылка — в подвале каждой страницы
404.html          Страница «не найдено» (на хостинге подключается через .htaccess)
robots.txt, sitemap.xml, favicon.*, icon-192.png, apple-touch-icon.png — для поисковиков (см. «SEO»)
legal.json        Реквизиты продавца и дата редакции политики — одно место для всех страниц
styles.css        Вся вёрстка и токены (цвета/шрифты — в :root)
fonts/            Playfair Display, Montserrat, Yeseva One (логотип), Marck Script —
                  woff2 рядом с сайтом, внешних запросов нет; @font-face — в начале styles.css
cloud.js          Наполнение разделов из Google Таблицы
main.js           Онлайн-запись, мобильное меню, тень шапки,
                  появление блоков при скролле
photos/           Настоящие фото в WebP (обработанные), к крупным — лёгкие версии *-sm / *-md для телефона;
                  map.webp — статичная карта, map-thumb.webp — её миниатюра для подвала
tools/            photos.js — сборка фото из оригиналов; upscale.mjs — нейро-увеличение слабых снимков;
                  build-map.js — пересборка карты под другой адрес; version.js — отпечатки версий в ссылках;
                  legal.js — расставляет реквизиты из legal.json по подвалам и политике;
                  pack.js — архив dist/krasota-site.zip для заливки на хостинг (TimeWeb);
                  seo.js — заголовки, canonical, Open Graph, микроразметка, robots.txt, sitemap.xml;
                  seo-assets.js + og-card.html — карточка для ссылок и значки сайта
sheet-template/   Шаблоны листов таблицы и поля анкеты мастера
```

Пункты меню «Обучение», «Мастер-классы» и «О нас» — якоря на секции главной.
Коворкинг, Услуги и Контакты — отдельные страницы.

## Онлайн-запись — главное, что нужно подключить

Запись у направлений разная. Ссылки задаются **в одном месте** — в начале `main.js`:

```js
var BOOKING = {
  anastasia: 'https://dikidi.net/1523754',  // Анастасия: ресницы и моментальный загар
  cowork:    'https://dikidi.net/1794550'   // аренда рабочих мест
};
```

Кнопка получает ссылку по значению атрибута — `data-book="anastasia"` или
`data-book="cowork"` — и открывает её в новой вкладке. Кнопка с пустым
`data-book` ведёт на блок записи `contacts.html#zapis`, где собраны все три варианта.

- **Коворкинг** (все кнопки страницы) — DIKIDI коворкинга.
- **Услуги**: блок «Услуги Анастасии» (ресницы, моментальный загар), общие кнопки
  и «Брови и ресницы» — DIKIDI Анастасии; остальные
  категории — на блок записи, пока у них нет своих мастеров.
- **Обучение, повышение квалификации, мастер-классы** — без онлайн-записи:
  «Для записи пишите в MAX» и телефон +7 (911) 128-01-22.

## Фотографии

Все фото на сайте — настоящие, из папки «Фото Анастасии». Сама папка в
`.gitignore` и на GitHub не попадает: там исходники HEIC и сторис с ученицами.
На сайт идут обработанные WebP-копии в `photos/`: каждая кадрирована под своё место,
приведена к одному тёплому тону (белые стены совпадают с кремовым фоном сайта),
у интерьеров добавлена «ясность» — локальный контраст фактуры. Крупные кадры лежат
в нескольких размерах (`*-sm`, `*-md`, полный) — браузер сам берёт подходящий.

**Пересобрать, когда пришли новые оригиналы:**

```
npm i sharp heic-convert
# положите файл в «Фото Анастасии», при необходимости поправьте кадр в tools/photos.js
node tools/photos.js                 # все фото
node tools/photos.js edu-neon        # только указанные
```

Источники из Telegram (меньше ~1000 px) мягкие и с артефактами сжатия, а на Retina браузеру
не хватает пикселей. Для них (в `tools/photos.js` помечены `sr: true`) есть нейро-увеличение:
`npm i @huggingface/transformers`, затем `node --use-system-ca tools/upscale.mjs`, потом снова
`node tools/photos.js`. Лучший способ улучшить такие снимки — попросить Анастасию прислать
**оригиналы файлом** (в Telegram: «отправить как файл»), а не как фото: Telegram пережимает
картинку до 1280 px. HEIC с телефона уже приходят в полном размере, там запас большой.

Стоковыми остались только карточки демо-мастеров на «Услугах» (`master-1/2.jpg` — исчезнут,
когда подключится таблица) и цветы-декор (`flowers.jpg`); миниатюра входа и аватары
(`entrance.jpg`, `anastasia-avatar.jpg`) сделаны один раз вручную.

## Наполнение из Google Таблицы

Разделы «Мастера», «Тарифы», «Какое место арендовать» и «Услуги» умеют
браться из Google Таблицы — владелец правит её сам, без правки кода.

Подключение — одна строка в начале `cloud.js`:

```js
var SHEET = '';   // сюда адрес Google Таблицы целиком
```

Таблице нужен доступ «Все, у кого есть ссылка → Читатель». Шаблоны листов
лежат в `sheet-template/` — их загружают в таблицу как листы «Мастера»,
«Тарифы», «Места», «Услуги». Изменения появляются на сайте за несколько
минут: Google кэширует ответ.

Как это устроено:

- Блоки помечены в разметке атрибутом `data-cloud` — скрипт находит их
  по нему и перерисовывает.
- Пока `SHEET` пустой или таблица недоступна, страницы показывают то,
  что вшито в HTML. Сайт не ломается и не пустеет — это и запасной
  вариант, и то, что видят поисковики.
- Секция «Наши мастера» на `services.html` скрыта, пока в таблице нет
  ни одной одобренной строки.
- Колонка «Показывать»: «нет» прячет строку, не удаляя её. Для листа
  «Мастера» пустая колонка тоже означает «не показывать» — это модерация
  анкет (`MODERATE_MASTERS` в `cloud.js`).
- Лист «Услуги», колонка «Мастер»: «Анастасия» — принимает она, кнопка «Записаться» ведёт в её DIKIDI; всё остальное (или пусто) —
  «мастер на выбор», кнопка «Подобрать мастера» ведёт на блок записи.
- Иконка подбирается по названию направления автоматически; колонкой
  «Иконка» её можно задать явно: зеркало, кушетка, стол, кресло, брови,
  ногти, макияж, волосы, косметология, депиляция.
- Цены пишутся в таблице как есть: «250 ₽», «от 1 200 ₽» — приставку «от» сайт
  сам не дописывает. В листе «Места» колонка «Количество» («3 места») необязательна,
  а в «250 ₽/час» жирным выводится только сумма. Ровно три тарифа сайт сам
  раскладывает в три колонки.
- Фото мастера: прямая ссылка на картинку либо ссылка на файл Google
  Диска — вторая превращается в прямую сама. Без фото рисуются инициалы.
- Кнопка на карточке мастера ведёт туда, что он указал в колонке
  «Контакт»: телефон становится звонком, ссылка на WhatsApp — чатом
  с готовым текстом, любая другая ссылка — переходом по ней. Если
  контакт не указан, имя мастера уезжает в адрес страницы записи
  (`contacts.html?m=Имя#zapis`), и там показывается, к кому пришёл
  человек — значение выводится через textContent, разметку из адреса
  вставить нельзя.

Мастера заполняют себя сами через Google Форму, привязанную к листу
«Мастера». Поля формы описаны в файле
`sheet-template/Анкета мастера — поля Google Формы.txt`.
Владелец только проверяет анкету и ставит «да» в колонке «Показывать».

## Юридическое (РФ)

- **Политика** — `privacy.html` (политика в отношении обработки персональных данных,
  152-ФЗ, ст. 18.1). Ссылка на неё — в подвале каждой страницы.
- **Реквизиты продавца** (ст. 9 Закона о защите прав потребителей) и e-mail для обращений
  по персональным данным лежат в одном файле — `legal.json`: ФИО ИП, ИНН, ОГРНИП, орган и
  дата регистрации, e-mail, дата редакции. После правки: `node tools/legal.js` — скрипт
  расставит их в подвалы всех страниц (строка «ИП … · ИНН … · ОГРНИП …» появляется, когда
  заполнены ФИО, ИНН и ОГРНИП). **Сейчас реквизиты не заполнены** — Анастасия данные пока не даёт.
  В тексте политики данных оператора нет по просьбе заказчика (п. 1.1, 1.4 и 7.2 называют только
  студию, адрес и телефон; обращения принимаются по телефону/в MAX и лично). Сведения о продавце
  требует ст. 9 Закона о защите прав потребителей — при первой возможности их стоит добавить.
  `node tools/legal.js --check` завершается ошибкой, пока что-то не заполнено.
- **Сайт сейчас ничего не собирает:** ни форм, ни cookie, ни аналитики, ни внешних запросов
  при открытии страниц. Политика говорит об этом прямо (раздел 5), поэтому **при любом из
  этих изменений её нужно обновить**:
  - подключение Google-таблицы (`SHEET` в `cloud.js`) — браузер посетителя начнёт обращаться
    к Google (таблица, миниатюры с Google Диска): поправить п. 5.1 или отдавать данные
    файлом со своего хостинга;
  - счётчик (Метрика и т. п.) или форма заявки — нужны уведомление/согласие, правки раздела 5
    и раздела 2, а данные граждан РФ при сборе должны попадать в базы в России
    (ч. 5 ст. 18 152-ФЗ; Google Формы для этого не годятся).
- **Подтвердить с Анастасией:** сроки хранения (3 года / год), перечень получателей данных
  (DIKIDI, мастера, MAX), «мы сами не передаём данные в другие страны», порядок со сведениями
  о здоровье (письменное согласие перед процедурой).
- **Язык.** С 1.03.2026 публичная информация для потребителей — на русском (ст. 10.1 Закона
  о защите прав потребителей, 168-ФЗ). Тарифы «Life / Standard / VIP» оставлены латиницей по
  просьбе заказчицы, над ними — русская подпись («Лайф», «Стандарт», «Вип»). Под тарифами —
  пояснение, что сертификат студии не является документом об образовании государственного образца.
- **Вне сайта** у заказчицы должны быть: уведомление Роскомнадзора об обработке персональных
  данных (клиентская база, онлайн-запись), письменные согласия на фото/видео (в том числе
  выпускниц на фото и на сертификатах), письменное согласие на сведения о здоровье, порядок
  хранения и уничтожения данных. Это не юридическая консультация — итоговую сверку делает юрист.

## SEO

Что сделано в самом сайте (всё это — невидимое для посетителя, но видно поисковикам и мессенджерам):

- **Заголовки и описания** страниц с ключевыми словами и городом («наращивание ресниц», «коворкинг»,
  «Гатчина»), по одному `<h1>` на странице.
- **canonical** на главный адрес `https://krasotalove.ru` — копия на GitHub Pages не считается дублем.
- **Карточка для соцсетей и мессенджеров** (Open Graph + Twitter): при отправке ссылки в MAX, Telegram
  или ВК показываются логотип, подпись и фото. Картинка — `photos/og-cover.jpg`, исходник — `tools/og-card.html`.
- **Микроразметка schema.org**: организация (`BeautySalon`: адрес, телефон, часы, координаты) на «Главной»
  и «Контактах», «хлебные крошки» на внутренних страницах — для Яндекса и Google (карты, сниппеты).
- **robots.txt и sitemap.xml**, **значки сайта** (`favicon.ico`, `favicon.svg`, `icon-192.png`,
  `apple-touch-icon.png`) для выдачи поисковиков и вкладок, своя страница **404**.
- Скорость: статика, WebP, шрифты свои, кэш в `.htaccess`; внешних запросов нет.

Как это обновлять:

- Домен, тексты заголовков и описаний, дата в sitemap — в начале `tools/seo.js`; затем `node tools/seo.js`
  (повторный запуск безопасен). Дату `LASTMOD` менять, когда меняется содержание страниц.
- Картинку для превью или значки — `tools/og-card.html` / `node tools/seo-assets.js` (нужен `sharp`).
- Часы 9:00–21:00 в разметке и на сайте пока из референса — подтвердить у Анастасии.

Что делать после запуска на домене (это вне сайта, и это даёт больше всего):

1. **Яндекс Вебмастер** — добавить сайт, подтвердить права (мета-тег добавить в `tools/seo.js`),
   отправить `sitemap.xml`, указать регион «Гатчина», запросить переобход значка сайта.
2. **Google Search Console** — то же: подтвердить, отправить sitemap.
3. **Яндекс Бизнес** (карточка на Яндекс Картах), **2ГИС**, **Google Business Profile** — адрес, часы,
   телефон, фото, ссылка на сайт. Для местного поиска («наращивание ресниц Гатчина») это важнее всего.
4. **Отзывы** на этих площадках и ссылка на сайт из профиля DIKIDI и соцсетей.
5. Значок в выдаче появляется не сразу: после индексации — от нескольких дней до пары недель.
6. Яндекс Метрику и другие счётчики пока **не ставим**: тогда нужны баннер/согласие на cookie и правки
   политики (раздел 5), а сейчас сайт ничего не собирает.

## Заливка на хостинг (TimeWeb)

1. `node tools/version.js`, затем `node tools/pack.js` — в `dist/` появятся папка `site` и архив
   `krasota-site.zip`: страницы, стили, скрипты, шрифты и только нужные фото, плюс `.htaccess`
   (сжатие и кэш). Папка `dist/` в git не попадает.
2. В панели TimeWeb: «Сайты» → создать сайт (папка латиницей) → «Файловый менеджер» → папка
   сайта `public_html` → удалить заглушку `index.html` и `cgi-bin` → «Архиватор» → «Загрузить и
   разархивировать» → `krasota-site.zip`. `index.html` должен лежать прямо в `public_html`.
3. Домен: «Домены и SSL» → добавить домен и привязать к сайту. Если домен куплен не в TimeWeb —
   у регистратора указать NS: `ns1.timeweb.ru`, `ns2.timeweb.ru`, `ns3.timeweb.org`,
   `ns4.timeweb.org` (делегирование 3–24 часа).
4. «Домены и SSL» → SSL-сертификаты → Let's Encrypt (бесплатно) для домена; когда станет активным —
   включить в настройках сайта «Использовать безопасное соединение https://».
5. Обновление сайта: снова `version.js` + `pack.js`, залить архив поверх (с заменой файлов).

## Телефон

- Ниже 820px шапка сворачивается в бургер, а внизу экрана появляется липкая
  панель с кнопками «Записаться» и звонком (`.mbar`, разметка в подвале
  каждой страницы). Она выезжает, когда первый экран пролистан.
- Фото в хиро и в шапках внутренних страниц на телефоне разворачиваются
  во всю ширину экрана со скруглением снизу — фирменная дуга остаётся
  на планшете и десктопе.
- Все кнопки в карточках и полосах на телефоне растянуты на всю ширину,
  минимальная высота 46px.
- Эффекты, которые на компьютере включаются наведением мыши, на сенсорных
  экранах (`@media (hover:none)`) работают от прокрутки и касания — классы ставит
  `main.js`: `.is-lit` — карточка или фото проходит середину экрана (свет, розовая
  кромка, значок разворачивается, фото чуть приближается), `.is-glint` — по фото
  пробегает блик (при выезде на середину и при касании), `.is-touch` — свет
  перескакивает под палец. Пятна в хиро сдвигаются при прокрутке, слайдер
  листается свайпом, кнопки и карточки вжимаются при нажатии. При «уменьшить
  движение» в настройках телефона всё это выключается.

## Мелочи

- `?static` в адресе отключает анимации появления — удобно для скриншотов
  и снятия макетов.
- Палитра и шрифты меняются в одном месте — блок `:root` в начале `styles.css`.
- Шапка и подвал одинаковые на всех страницах: правите в одном файле —
  не забудьте перенести в остальные три.
- Внешних запросов у сайта нет вообще: шрифты, карта и фото локальные.
